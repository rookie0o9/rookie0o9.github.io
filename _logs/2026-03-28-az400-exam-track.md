The wrong way to approach an exam is to start with a study guide and work forward. The right way is to map what you already know against the domain list, identify the gaps, and fill only those.

This is that mapping exercise for AZ-400.

## What AZ-400 actually tests

Five domains, roughly weighted:

| Domain | Weight |
|---|---|
| Build and release pipelines | ~40% |
| Source control strategy | ~15% |
| Security and compliance plan | ~15% |
| Instrumentation strategy | ~10% |
| Processes and communications | ~10% |

The pipeline domain is almost half the exam. That is where the existing work sits.

## What the current delivery work already covers

**Build and release pipelines (~40%)**

The Terraform delivery backbone covers this domain in depth: plan/apply pipeline separation, artefact management, environment gates, YAML pipeline structure, and agent configuration. The remote state and WIF posts cover the underlying infrastructure that makes those pipelines safe.

Covered: pipeline structure, approval gates, artefact promotion, IaC delivery patterns.

**Security and compliance (~15%)**

Workload identity federation eliminates credential management from the pipeline. RBAC-only state storage removes access keys. The Foundry lab covers governance-first deployment.

Covered: federated credentials, least-privilege access, secrets elimination.

**Source control strategy (~15%)**

Repo structure with scope-bounded modules, branch policy configuration, and pull request-based delivery are already in use. The backbone series documents the repo layout decisions.

Partially covered: branching strategy documented, PR policies need formalising.

## What is not yet covered

**Instrumentation strategy (~10%)**

Log Analytics workspace integration, alert rules, Azure Monitor query patterns, and feedback loops into the pipeline. This is the next substantive gap.

**Processes and communications (~10%)**

Azure Boards configuration, work item tracking, sprint planning integration with pipeline gates. Lighter domain but needs at least one lab pass.

**Dependency management**

Package feeds, Artifacts configuration, upstream sources. Not yet touched.

## What comes next

Three areas, in order:

1. Log Analytics integration — connect pipeline runs and infrastructure events to a workspace, write the query runbook
2. Azure Artifacts — set up a feed, publish a module, consume it from a pipeline
3. Azure Boards policies — branch policies tied to work item state

The instrumentation lab comes first because it is the most operationally useful beyond the exam.
